Queries:

  • which species dominates each lake? (largest slice)
  • how does species composition vary across geography?
  • which lakes have similar mixes? (visual comparison)
This is composition — nesting one query-affording structure inside another. It's the same idea as faceting: spreading a chart-making function. Pie affords proportion queries easily; magnitude queries are hard because arc angle is a weaker encoding than length. Cross-lake magnitude comparison is impossible because pies are normalized. ~18 min mark.

the takeaway is a sentence

"Every variety decreased at every site — except Morris, where every variety increased." 

def mark_slope(data):
    point_name = f"slope-pts-{data[0]['site']}"
    return layer([
      chart(data)
        .flow(
          group(by="variety"),
          scatter(x="year", y="yield")
        )
        .mark(rect(w=0, h=0, fill="variety").name(point_name)),
      chart(selectAll(point_name))
        .flow(group(by="variety"))
        .mark(line(strokeWidth=2)),
    ])

chart(barley)
  .flow(spread(by="site", dir="x", spacing=20))
  .mark(mark_slope)

Six site panels, ten variety-lines each. Morris tilts up across the board; every other panel tilts down, save one stray line apiece in University Farm and Grand Rapids.

Facets by site with the mark-as-function pattern (same idiom as FacetedChart.stories.tsx): the outer spread makes six scopes, and each scope's mark function draws its own little chart. The connecting line reuses the exact "name it, select it, group it, connect it" idiom the ribbon slide already taught — swap `area` for `line`. One quantifier (site) is a scan across panels; the other (variety) is a scan down each panel's ten lines; the sign predicate is read off each line's slope, one at a time. This is Trellis-style: Becker & Cleveland's own display for this dataset. It's precise on magnitude — you can read off exactly how much each variety fell or rose — but the reader still has to aggregate ten slope signs per panel to recover the sentence. Compare to the next slide's heatmap, which gives up magnitude precision to make the sign read as a single glance.

compile the sentence

chart(barley)
  .flow(
    derive(pair_years),
    table(by={"x": "variety", "y": "site"}, spacing=4)
  )
  .mark(
    rect(fill="deltaColor")
  )

derive computes the compared term — Δyield per (site, variety). table crosses the sentence's two quantifiers, variety and site, into a grid where neither is privileged. The fill is the predicate: sign of Δ, on a diverging scale centered at zero, anchored on Morris orange. One orange row; the rest, blue.

One green row (Morris) in an otherwise red matrix. Two other cells buck their row's sign, and they're not faint: Grand Rapids/Velvet rose +9.2 bushels/acre, the largest increase anywhere outside Morris — bigger than several of Morris's own varieties. University Farm/No. 475 rose a more moderate +5.3. Both are real data, not a chart bug; they just aren't uniform the way Morris's whole row is. `derive` is term-level computation: gofish-graphics's built-in `gradient()` color scale always spans the field's actual min/max, so it can't be recentered at 0 for an asymmetric spread of deltas — the diverging scale here is hand-built with chroma and baked into a literal per-row hex field instead. `table` is quantifier structure — crossed spreads, neither privileged. `rect`'s fill is predicate evaluation. Choosing a chart is compiling the sentence.

def balloon(x, y, scale, colors):
  return Frame(
    [
      ellipse(cx=15, cy=15, w=24, h=30, fill=colors["body"]),
      ellipse(cx=12, cy=11, w=7, h=11, fill=colors["highlight"]),
      rect(cx=15, cy=32, w=8, h=4,
        fill=colors["knot"], rx=3, ry=2),
      rect(cx=15, cy=32, w=5, h=2.4,
        fill=colors["knot"], rx=2, ry=1),
    ],
    x=x - 15 * scale,
    y=y + 27 * scale,
    box=True,
    transform={"scale": {"x": scale, "y": -scale}},
  )

each operator buys a query

Operator places the query it makes cheap
spread one slot per value of a field
compare ⟨…⟩ across values slots sit side by side — one scan
stack scopes tiled end to end; boundaries at the running totals
read ⟨the total⟩ at the endpoint read ⟨shares⟩ when normalized segments tile end to end — a boundary read
scatter each entity at its location in space
compare ⟨two measures⟩ at once points share one frame — a gestalt of the cloud
area / line / ribbon nothing new — draws over existing placements
follow ⟨an entity⟩ across scopes strokes connect endpoints — a trace
table two independently addressable axes
look up ⟨a value⟩ at field × field cells align in rows and columns — a scan either way
spread — discrete; alignment & uniform density.
stack — partitioned continuous; part-to-whole.
scatter — continuous × continuous; proximity.
area / line / ribbon — continuous or contiguous; connection.
table — discrete × discrete; uniform density.

Every operator does two jobs: an addressing move (what's where, what's locatable) and a pricing move (which readings become one perceptual act). Connection is the only pure pricing move — and the scatterpie works by keeping scatter's addressing while swapping the value payload.

The scatterpie composes two of these: scatter contributes how the distribution varies across space, the pie glyph contributes share-within-entity.

Connection overrides adjacency at its endpoints (Palmer & Rock) — the strongest carrier, and the most targeted.
