waffle mark

def waffle(count, fill, columns=5):
  return flow(
    repeat(count), chunk(columns),
    spread(dir="y", reverse=True), spread(dir="x"),
  ).mark(rect(w=8, h=8, fill=fill))
First pair, same seafood data. The left sizes each segment continuously; the right chunks the same counts into unit squares. The outer lake spread stays in place, while the continuous species stack becomes repeat, chunk, and two small spreads. An eyeballed "share of the total" becomes an exact "count squares," because the units are countable atoms.

one more level

chart(titanic)
  .flow(
    stack(by="class", dir="y", size=field("count").normalize()),
    stack(by="sex", dir="x", size=field("count").normalize()),
    stack(by="survived", dir="y", size=field("count").normalize())
  )
  .mark(rect(fill="survived"))
Second pair, Titanic data, and this one has teeth. The two-level mosaic answers the class question directly: Third class survived at 25.2%, Crew at 24.0%, so third class fared better. Add the sex level and the answer flips within BOTH sexes: among men, Crew 22.3% vs Third 17.3%; among women, Crew 87.0% vs Third 45.9%. The mechanism: the crew is 97% male, and men survived at far lower rates everywhere, so the crew's aggregate is dragged down below Third's. Simpson's paradox, the extra for-each isn't decoration, it changes the verdict. Next: one more move (connect, then sort) before the counterexample.

chart(energyMix)
  .flow(
    spread(by="year", dir="x"),
    stack(by=field("source").sort("amount"), dir="y")
  )
  .mark(rect(h="amount", fill="source"))
  .layer(ribbon(by="source", opacity=0.5))

UK electricity generation · Our World in Data / Ember

Third move, in three stages. First, sort each year's stack by amount: rank reads as position, but sorting re-purposes position from an identity channel to a rank channel, so following one source across years is a color hunt. Then connect instead: the bands carry "same source" identity across years, but in fixed stacking order they never cross, so there's nothing to read at a crossing. Compose them and the combination pays off: with rank as position AND identity as continuity, a crossing IS a rank inversion, an overtake event, read directly. Real data: UK share of electricity generation (Our World in Data / Ember). Wind passes Coal between 2014 and 2018, Coal collapses 29.6% to 5.0%, so Nuclear passes it too, then Wind passes Nuclear between 2018 and 2022, and Solar passes Coal by 2022: renewables overtaking legacy sources one crossing at a time. Contrast with the barley walkthrough this replaced: there the story was sign-of-change (did each variety rise or fall?), and the ribbon answered an adjacent rank question, the slope panels carry that beat now. Rank change is the query ribbons are actually FOR, so the ribbon lives here.

layer on labels

chart(bottleData, axes=False)
  .flow(spread(by="category", dir="x", spacing=20))
  .mark(
    layer([
      paint([
        image(href=bottlePng, h=datum(100)),
        rect(h="amount", w=175, fill="green"),
      ], blendMode="color").name("bottle"),
      rect(h=1, y="amount", fill="gray").name("line"),
      text(text="{amount}%", fill="gray").name("label"),
    ]).constrain(lambda bottle, line, label: [
      Constraint.align([bottle, line], x="start"),
      Constraint.distribute([line, label], dir="y", spacing=0),
      Constraint.align([label, line], x="end"),
    ])
  )

Pictorial composition grammar adapted from PiCCL · Shi et al., IEEE VIS 2025

Hold the query fixed: compare the fill shares across bottles. First, turn the normalized bars into bottle pictorials with paint. Then add the fill rule and percentage labels as another layer, constrained to their fill level. The richer presentation makes the values easier to read, but it does not change what the reader can ask of the data.

Titanic passengers: class, sex, survived. Three stacks, nested, alternating direction, each normalized within its parent scope. Read it: within every class, women survived at higher rates, "women and children first" as one uniform visual sentence, and survival falls from first class to third within each sex. Note this is the Charlie-and-River move again: swapping the nesting order changes whether you read "survival by sex, within each class" or "survival by class, within each sex." A mosaic isn't in the chart-type dropdown of most tools; here it's the operator we already know, composed one level deeper.

the same moves, stranger structures

Escalation beat. The moves the audience just learned, spread, stack, nest, restyle, don't stop where the chart menu does. Walk the six examples: polar ribbon, insertion sort, multilevel silhouette tree, layered bars and area, Titanic fare circle treemap, and flower chart. Each pushes a familiar operation further: wrap and connect; align and constrain; switch templates inside a hierarchy; layer bars with ribbons; pack circles by fare; replace bars with multivariate glyphs. They are not six new primitive chart types. They are the same small structural vocabulary composed in six different ways. [advance] Keep composing the same moves and you run out of chart names.

Why "more"

a grammar of more graphics

The Grammar of Graphics fits inside GoFish, and so do grammars beyond it.

GoFish's own test gallery reimplements, example by example:

  • vega-lite: the grammar underneath Altair
  • Atom: unit & dot-plot charts
  • PiCCL: pictorial charts (the bottle)
  • GoTree: a tree-layout grammar, 46 gallery examples
  • seaborn-style jointplots, and Bluefish diagrams
This is the sense of "more." These aren't screenshots of other tools, each of these grammars exists as a folder of working examples in GoFish's own test suite. The vega-lite gallery is the engine underneath Altair, so the charts Altair makes easy stay easy. And the grammars Altair and matplotlib can't reach, unit charts, pictorials, tree layouts, diagrams, are the same operators composing further, not custom SVG code. The standard grammar is a subset; the composition keeps going where the chart-type menu stops.

takeaways

1. Graphics are visual data structures that we query with our eyes.

2. GoFish makes visual structure composable, letting us build familiar charts and continue beyond what conventional visualization grammars make easy.

3. Start with what the reader needs to see, then build the structure that makes it easy.

Land all three explicitly. 1: the central thesis, graphics are visual data structures and reading them means querying that structure with our eyes. 2: the GoFish contribution, those structural moves are directly authorable and keep composing after the conventional chart vocabulary runs out. 3: the design method, start from the reader's question and build the structure that makes it easy to answer. Then the honest close: GoFish is one attempt, Q&A is needfinding. ~27 min mark.
