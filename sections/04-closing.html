which species dominates each lake?

First move, in two steps. All three charts carry the same per-lake species shares. Bars to pies is stack-to-clock coordinates — note the chips are identical, because that step is a pure restyle. Nothing gained, nothing lost (hold that thought for the last slide). Pies to scatterpie is the structural step: the glyphs land at each lake's real position, and the chip gains the highlighted clause — composition is now answerable AT a place, so "what's happening in the north?" is one glance instead of a lookup.

how many fish, exactly?

for each lake for each species count squares
Second pair, same seafood data. The left sizes each segment continuously; the right chunks the same counts into unit squares. The nested for-eaches are identical — what changes is the last line: an eyeballed "share of the total" becomes an exact "count squares," because the units are countable atoms.

moves that change the query

move 3 of 3 · one more level

did third class fare better than crew?

for each class share who survived
→

add sex: the answer flips

for each class for each sex share who survived

one level short, the chart says the opposite. (Simpson's paradox)

Third pair, Titanic data — and this one has teeth. The two-level mosaic answers the class question directly: Third class survived at 25.2%, Crew at 24.0%, so third class fared better. Add the sex level and the answer flips within BOTH sexes: among men, Crew 22.3% vs Third 17.3%; among women, Crew 87.0% vs Third 45.9%. The mechanism: the crew is 97% male, and men survived at far lower rates everywhere, so the crew's aggregate is dragged down below Third's. Simpson's paradox — the extra for-each isn't decoration, it changes the verdict. The next slide is the counterexample: a move that changes nothing.

a move that doesn't

ordinary normalized bars

for each bottle share of full
→

how full is each bottle?

for each bottle share of full

same query. different voice.

Not every move is structural. The bottles are a paint-composited pictorial dressed over four ordinary normalized bars, one per bottle — same "share of full" chip on both sides, because the query hasn't moved at all. What changed is voice, not structure: a fill line and a bottle photo standing in for a rectangle. Useful, memorable even, but it's a style choice layered on the same chart, not a new question the reader can ask.

three stacks make a mosaic

const share = field("count").normalize()

chart(titanic)
  .flow(
    stack({ by: "class",    dir: "y", size: share }),
    stack({ by: "sex",      dir: "x", size: share }),
    stack({ by: "survived", dir: "y", size: share })
  )
  .mark(
    rect({ fill: "survived" })
  )

No new operators — just stack three deep. Cell area is the joint count; the blue fraction is the survival rate. And the nesting order decides which comparison you read first — the same choice as the grouped bars that opened the talk.

Titanic passengers: class, sex, survived. Three stacks, nested, alternating direction, each normalized within its parent scope. Read it: within every class, women survived at higher rates — "women and children first" as one uniform visual sentence — and survival falls from first class to third within each sex. Note this is the Charlie-and-River move again: swapping the nesting order changes whether you read "survival by sex, within each class" or "survival by class, within each sex." A mosaic isn't in the chart-type dropdown of most tools; here it's the operator we already know, composed one level deeper.

Escalation beat. The moves the audience just learned — spread, stack, nest, restyle — don't stop where the chart menu does. [advance] The operator captions are the point: the sankey is spreads and stacks with ribbons connecting named tiers; the rose is the stacked bar wrapped into clock coordinates — polar is a coordinate change on structure we already built, not a new chart family. The sunburst and the orthogonal tree come from GoTree, a tree-layout grammar embedded in GoFish. None of these four has a slot in the dropdown; all four are the same composition, carried further.

diagrams are visual data structures too

"We have three pulleys, two weights, and some ropes, arranged as follows:

  1. The first weight is suspended from the left end of a rope over Pulley A. The right end of this rope is attached to, and partially supports, the second weight.
  2. Pulley A is suspended from the left end of a rope that runs over Pulley B, and under Pulley C. Pulley B is suspended from the ceiling. The right end of the rope that runs under Pulley C is attached to the ceiling.
  3. Pulley C is attached to the second weight, supporting it jointly with the right end of the first rope.

[…] Find the ratio of the second to the first weight, if the system is in equilibrium."

Larkin & Simon 1987, "Why a Diagram Is (Sometimes) Worth Ten Thousand Words"

The same operators drew this. The structure language already reaches diagrams — the query language for them is open research.

And the strange diagrams from the start of the talk? Same moves, within reach.

look up what this rope attaches to follow the rope through the pulleys compare which side is heavier
Horizon slide — cut it first if time runs short. Larkin and Simon's classic: the paragraph and the diagram carry exactly the same information, but they are not computationally equivalent. Their claim is the talk's thesis stated for diagrams in 1987 — a diagram earns its keep by making the right inferences cheap. And this diagram is not clip art: it's the GoFish docs-gallery export of the Bluefish pulley example, drawn by the same layers, alignment, and constraints as everything else today — the structure language already reaches diagrams. What's open is the query side: the chips we've been writing all talk say for-each and share; a diagram's queries are richer — incidence, attachment, which way does it turn — and a query language for those is where the research goes next. That's why this chip is dashed: speculative, like the two-languages slide's invitation — please push back on it. Why "more"

a grammar of more graphics

The Grammar of Graphics fits inside GoFish — and so do grammars beyond it.

GoFish's own test gallery reimplements, example by example:

  • vega-lite — the grammar underneath Altair
  • Atom — unit & dot-plot charts
  • PiCCL — pictorial charts (the bottle)
  • GoTree — a tree-layout grammar, 46 gallery examples
  • seaborn-style jointplots, and Bluefish diagrams
This is the sense of "more." These aren't screenshots of other tools — each of these grammars exists as a folder of working examples in GoFish's own test suite. The vega-lite gallery is the engine underneath Altair, so the charts Altair makes easy stay easy. And the grammars Altair and matplotlib can't reach — unit charts, pictorials, tree layouts, diagrams — are the same operators composing further, not custom SVG code. The standard grammar is a subset; the composition keeps going where the chart-type menu stops.

takeaways

1. Chart types are great shortcuts, but graphics are really sophisticated visual structures.

2. Changing this structure changes what your reader can and can't see in (probably) predictable ways.

3. Thinking structurally helps us move beyond familiar charts and rigid rules to designs that might better fit our data or task.

Land all three explicitly. 1: the Part 1 journey — bar, stacked, sorted, ribbon, polar — weren't different chart types, they were structural moves. 2: affordances thread — every move opens some queries and closes others. 3: the composition payoff — scatter-pie, flower, balloon weren't in any dropdown. Then the honest close: GoFish is one attempt, Q&A is needfinding. ~27 min mark.
